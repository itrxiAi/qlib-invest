# 资讯同步与分析工作流

输入是 `runs/news_raw/` 下的最新归档，输出是更新后的 `briefing.md`、深度分析存档、TG 推送。

每个 Phase 产出具体 artifact，喂给下一个 Phase。不要跳过，不要合并。

## Artifact Paths

- `runs/briefing.md` — 当前局势简报（跨 session 记忆），标题下第一行为 `> 上次更新：{YYYY-MM-DD HH:MM}`
- `runs/causal_rules.md` — 因果方向规则库
- `runs/news_raw/{date}_techmeme.md`、`runs/news_raw/{date}_twitter.md` — 原始资讯
- `runs/news_deep/{date}_{hour}.md` — 本轮深度分析存档

## 通用约定

**标注**：未确认的事实在句内标 `[未验证]` / `[单一来源]` / `[机制未验证]`；非 news_raw 来源标 `[Web补充]`。已多源确认的不标，不设"验证状态"行。

**置信度**：`[高/中/低]`。带上述任一标注的事实不得支撑 `[高]`。判断的强度不能超过证据的强度——宁可写"这事我没验证清楚"，也不要用肯定语气填补空白。

**社交信号**：🔁100+ 或 ❤500+ = 高热度信号；❤<50 的单一社交来源只作线索，须权威源确认后方可作事实引用。

## Phase 1: 加载上下文

用 `Read` 读 `runs/briefing.md`，不要依赖记忆。搞清在追踪什么、哪些判断已有置信度、哪些假设待验证。

文件不存在则按 Phase 4b 的章节结构建空文件，`上次更新` 留空。

**输出**：当前状态的心智模型。

## Phase 2: 去重与粗筛

窗口 = briefing.md 的 `上次更新` 至当前时间；该字段为空则取当天。用 `Glob` 列出窗口内所有 `*_techmeme.md` / `*_twitter.md`（不限于今天，防止 briefing 断更期间的资讯被静默跳过），`Read` 并行读取。

news_raw 偏科技，宏观/央行/外汇/债券/地缘是盲区。用 `WebSearch` 检索当前市场焦点补齐，标 `[Web补充]`。若焦点与丢弃清单中的条目相关（如前兆信号被误当"例行表态"），回收该条目重新分类。

### 分类

同一事件 = 相同主体（公司/国家/人物）+ 相同话题（同一军事行动、同一融资、同一政策）。

- `[新增]` — 历史中无相关条目
- `[更新]` — 同一事件的新进展（"伊朗宣布关闭海峡" → "不允许任何船只通过" 是升级，算更新）
- 丢弃 — 内容几乎相同、无新信息的重复报道；或娱乐/社会/个人观点/营销稿/转发感谢

### 粗评分

给每条 `[新增]`/`[更新]` 打 1-5 分，依据事件性质 + 社交信号：

- **5** 重大突发 — 战争/停火、紧急加息降息、重大黑天鹅、系统性风险
- **4** 重要事实 — 超预期数据、重大融资并购落地、政策出台、关键人物突发表态
- **3** 有价值但非紧急 — 外交进展、行业趋势、官员常规表态、已知事件延续
- **2** 例行更新 — 指数日常数值、常规会议、重复表述
- **1** 噪音

1-2 分不进 Phase 3，列入备查清单（一行标题，不做深度分析、不联网验证）。

**输出**：≥3 分的待分析列表（每条带标注、来源、时间、链接、初评分）+ 备查清单 + 丢弃清单（标题 + 丢弃原因，各一行）。三份清单相加必须覆盖窗口内全部资讯（含 `[Web补充]`），不允许静默遗漏。

## Phase 3: 深度分析

对 Phase 2 放行的条目逐条分析。**挖因果链，不是复述事实。** 换种说法就能当新闻摘要用，说明你在复述。

先 `Read` `runs/causal_rules.md`，按第 0 层元规则判定当前 regime，再套用分领域规则。规则库自身的使用约定（偏离须显式写出、强度含义）以该文件为准。

- **挂规则：** 涉及资产价格与宏观传导的箭头必须对应规则库中的一条规则，并沿用其时间尺度。人事、诉讼、产品发布等纯事件性机制不强制挂规则。
- **挖到底：** 因果链要挖到结构性原因。"SpaceX 跌因为股价跌"是同义反复；"xAI 吃掉 capex → 本质是 AI infra 公司 → 市场质疑内部补贴"才是原因。
- **写路径不写名单：** 传导每一环都要回答"通过什么机制"。不要写"利好 X、利空 Y"——本项目不预测利好利空。
- **反常优先：** 价格变动与规则预测方向相反时（放鹰中黄金涨、收益率上行而美元弱、避险升温而加密涨），先做 M1 归因再写传导。动用规则例外条款须验证例外条件本身，验不了标 `[未验证]` 且禁入核心判断。反向变动是当轮最强信号之一，单独成条，不得用括号或跨事件关联里的一句带过。
- **跨事件收敛：** 指出本轮多条资讯共同指向的信号。"与上轮判断一致"不算关联。
- **反面假设：** 写清主流叙事错了的最可能原因**及其成立条件**。没有成立条件的反面假设是装饰。

分析后可上下调 1 分并注明理由；调整后 <3 分的移入备查清单。

### 交叉验证

用 `WebSearch` 验证关键事实，同一条目 3 轮无果 → 标 `[未验证]` 继续，不卡住。

- **机制同标准：** "X 导致/劝说 Y" 与事实断言同等验证。验不了就改或然句式（"可能/或"），不得以肯定语气写出。
- **一手与推算分开：** SEC/央行/官方声明确认的数字，与第三方推算、媒体估算分开标注，不可打包成一个确认状态。
- **如实报告：** 没验证就说没验证，绝不把第三方推算写成一手确认。写入核心判断的每条须有权威源支撑。
- **量级校准：** 用 `Read` 查 `runs/news_deep/` 中类似事件当时的实际影响，避免高估或低估本轮。

### 输出格式

全流程唯一格式，Phase 4 的存档与推送沿用：

```
## 本轮综合判断
[1-3 句概括本轮多条资讯共同指向的信号]

## 逐条分析

★★★★★ 事件标题（你总结的，不是原文标题）（来源 时间）
  因果链：为什么发生
  影响传导：通过什么机制影响谁
  跨事件关联：跟本轮/历史哪些事件共同指向什么信号
  反面假设：如果主流叙事错了，最可能的原因和成立条件
  置信度：[高/中/低]

★★★★☆ ...
```

## Phase 4: 存档 + 更新 briefing + 推送

### 4a. 存档

`Write` 到 `runs/news_deep/{date}_{hour}.md`：

```markdown
# 投研深度分析 — {date} {hour}:00
_分析时段：{date} {hour}:00_

{Phase 3 的完整输出}
```

### 4b. 更新 briefing.md

用 `Edit` 更新 `runs/briefing.md`，章节固定为：

- **上次更新**：标题下第一行的时间戳，写本轮时间
- **核心判断**：3-5 条当前最重要的判断，每条带置信度
- **追踪中事件**：表格（事件/状态/上次更新/置信度）
- **待验证假设**：新增/更新/删除
- **本轮新增**：本轮关键资讯
- **已归档**：不再活跃的旧事件

修正旧判断时必须在"本轮新增"中标注 `[修正]`，不要静默改。

### 4c. TG 推送

对评分 ≥4 的事件，沿用 Phase 3 格式（标题行 + 因果链 + 影响传导两行即可），首行 `📊 投研深度分析 {date} {hour}:00`，其后接本轮综合判断。超过 4000 字符分段发送。

```bash
source .env && curl -s -X POST "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage" \
  -d "chat_id=${TELEGRAM_CHAT_ID}" \
  -d "text=消息内容"
```

**输出**：存档文件、更新后的 briefing.md、TG 推送确认。

## Phase 5: 自审

重读 `briefing.md` 和本轮存档，检查：

- 每条核心判断都有权威源支撑，句内无标注
- 覆盖核对：待分析 + 备查 + 丢弃三份清单覆盖窗口内全部资讯
- 数字复算：每条抽查一个派生数字，用原始数字复算（"-50%" 必须等于 (峰值−现价)/峰值）
- 有无未做 M1 归因的收益率变动，或被括号带过的规则矛盾
- 动机分析没有流于表面（"谁受益"要写具体利益机制，不能只写公司名）
- 评分没有通胀（5 分必须是真正的重大突发）
- 该修正的旧判断没被静默跳过

发现问题回到对应 Phase 修正。两轮干净才过。

## Phase 6: 输出

向用户报本轮摘要：复用 Phase 3 的综合判断，加上新增了什么、哪些判断被修正、推送了哪些到 TG。简洁。

## Iteration Rules

- Phase 3 对单条资讯最多 3 轮 `WebSearch`，无果标 `[未验证]` 继续，不卡住
- Phase 5 发现问题回到对应 Phase 修正后重新自审
- Phase 3-5 之间循环超过 3 次必须向用户报告
