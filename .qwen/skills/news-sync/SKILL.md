# 资讯同步与分析工作流

输入是 `runs/news_filtered/` 下的最新归档，输出是更新后的 `briefing.md`、深度分析存档、TG 推送。

## Artifact Paths

- `runs/briefing.md` — 当前局势简报（跨 session 记忆），标题下第一行为 `> 上次更新：{YYYY-MM-DD HH:MM}`
- `runs/causal_rules.md` — 因果方向规则库
- `runs/news_filtered/{date}_techmeme.md`、`runs/news_filtered/{date}_twitter.md` — 原始资讯
- `runs/news_deep/{date}_{hour}.md` — 本轮深度分析存档

## 通用约定

**社交信号**：🔁100+ 或 ❤500+ = 高热度信号；❤<50 的单一社交来源只作线索，须权威源确认后方可作事实引用。

## Phase 1: 加载上下文

用 `read_file` 读 `runs/briefing.md`，不要依赖记忆。

文件不存在则按 Phase 4b 的章节结构建空文件，`上次更新` 留空。

**输出**：当前状态的心智模型。

## Phase 2: 去重与粗筛

窗口 = briefing.md 的 `上次更新` 至当前时间；该字段为空则取当天。用 `run_shell_command` 执行 `find runs/news_filtered -name '*_techmeme.md' -o -name '*_twitter.md'` 列出窗口内所有文件，`read_file` 并行读取。

用 `web_search` 补齐 news_filtered 可能遗漏的当前市场焦点，补到的条目与 news_filtered 统一分类、统一评分。

### 分类

同一事件 = 相同主体 + 相同话题。

- `[新增]` — 历史中无相关条目
- `[更新]` — 同一事件的新进展
- 丢弃 — 内容几乎相同、无新信息的重复报道；或娱乐/社会/个人观点/营销稿/转发感谢

### 粗评分

给每条 `[新增]`/`[更新]` 打 1-5 分，依据事件性质 + 社交信号：

- **5** 重大突发 — 战争/停火、紧急加息降息、重大黑天鹅、系统性风险
- **4** 重要事实 — 超预期数据、重大融资并购落地、政策出台、关键人物突发表态
- **3** 有价值但非紧急 — 外交进展、行业趋势、官员常规表态、已知事件延续
- **2** 例行更新 — 指数日常数值、常规会议、重复表述
- **1** 噪音

1-2 分不进 Phase 3，列入备查清单（一行标题，不做深度分析、不联网验证）。

**输出**：≥3 分的待分析列表（每条带来源、时间、链接、初评分）+ 备查清单 + 丢弃清单（标题 + 丢弃原因，各一行）。三份清单相加必须覆盖窗口内全部资讯，不允许静默遗漏。

## Phase 3: 深度分析

对 Phase 2 放行的条目逐条分析。**挖因果链，不是复述事实。**

先 `read_file` 读 `runs/causal_rules.md`，分析时结合规则库判定因果方向。

- **挖到底：** 因果链要挖到结构性原因，不要停留在表象重复。
- **写路径不写名单：** 传导每一环都要回答"通过什么机制"。不要写"利好 X、利空 Y"——本项目不预测利好利空。
- **反常优先：** 价格变动与规则预测方向相反时，重点关注，单独成条。
- **跨事件收敛：** 指出本轮多条资讯共同指向的信号。

分析后可上下调 1 分并注明理由；调整后 <3 分的移入备查清单。

### 量级校准

用 `read_file` 查 `runs/news_deep/` 中类似事件当时的实际影响，避免高估或低估本轮。

### 输出格式

Phase 4 存档与推送沿用此格式：

```
## 本轮综合判断
[1-3 句概括本轮多条资讯共同指向的信号]

## 逐条分析

★★★★★ 事件标题（你总结的，不是原文标题）（来源 时间）
  因果链：为什么发生
  影响传导：通过什么机制影响谁
  跨事件关联：跟本轮/历史哪些事件共同指向什么信号
★★★★☆ ...
```

## Phase 4: 存档 + 更新 briefing

### 4a. 存档

`write_file` 到 `runs/news_deep/{date}_{hour}.md`：

```markdown
# 投研深度分析 — {date} {hour}:00
_分析时段：{date} {hour}:00_

{Phase 3 的完整输出}
```

### 4b. 更新 briefing.md

用 `edit` 更新 `runs/briefing.md`，章节固定为：

- **上次更新**：标题下第一行的时间戳，写本轮时间
- **核心判断**：3-5 条当前最重要的判断
- **追踪中事件**：表格（事件/状态/上次更新）
- **本轮新增**：本轮关键资讯
- **已归档**：不再活跃的旧事件

修正旧判断时必须在"本轮新增"中标注 `[修正]`，不要静默改。

**输出**：存档文件、更新后的 briefing.md。

## Phase 5: 自审

重读 `briefing.md` 和本轮存档，确认覆盖了窗口内全部资讯，无静默遗漏。

## Phase 6: 输出

向用户报本轮摘要：综合判断 + 新增/修正了什么。简洁。

## Iteration Rules

- Phase 3 对单条资讯最多 3 轮 `web_search`，无果继续，不卡住
- Phase 3-5 之间循环超过 3 次必须向用户报告
